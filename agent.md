## Обзор проекта

**Talker Box** — десктопное приложение для голосового ввода текста (push-to-talk). 
  Пользователь зажимает горячую клавишу → говорит → отпускает → текст распознаётся и вставляется в активное окно символами через SendInput (буфер обмена НЕ используется и не затирается).

**Стек:** Python 3.13.15, PyQt6, sherpa-onnx (GigaAM v3 trans-punct, 220 МБ), sounddevice, pyperclip  
**Платформа:** Windows 10/11  
**Пользователь:** GOLDMAN, работает в cTrader, Node.js, C# WinForms  
**GitHub:** https://github.com/mihalanius/Talker-Box.git

## Архитектура горячей клавиши

### Текущая реализация: In-process WH_KEYBOARD_LL hook

```
main.py → hotkey_hook.py (HotkeyListener)
         → SetWindowsHookExA(WH_KEYBOARD_LL) в отдельном потоке
         → GetMessageW loop
         → callback("DOWN"/"UP")
         → QTimer.singleShot в main.py
```

**hotkey_hook.py:**
- `HotkeyListener` — класс с WH_KEYBOARD_LL хуком
- `parse_hotkey()` — парсит строки типа `ctrl+win`, `f9`, `ctrl+shift`
- `start_capture(callback)` — QTimer-based захват горячей клавиши
- `stop()` — unhooks directly

**Ключевые находки:**
- `CFUNCTYPE`: `ctypes.CFUNCTYPE(ctypes.c_long, ctypes.c_int, wintypes.WPARAM, ctypes.c_void_p)`
- `CallNextHookEx` lParam: передавать `ctypes.c_void_p(lParam)` для избежания OverflowError
- `GetMessageW` обязателен для WH_KEYBOARD_LL — `MsgWaitForMultipleObjects` НЕ работает
- Подпроцесс с CREATE_NO_WINDOW блокирует хуки — хук должен работать in-process
- Win key перехватывается ОС — Qt `keyPressEvent` его не видит
- Ctrl+Win: ОС генерирует синтетические UP events — fix: подавлять ALL key DOWN пока combo активно

### Режимы работы

- **Hold** (по умолчанию): запись пока зажата клавиша, стоп при отпускании
- **Toggle**: одно нажатие — старт, следующее — стоп

## Стриминг и облако (v2.2 — перенос из клона «Talker Box Стриминг»)

Режим живого распознавания: текст появляется по мере речи в облачке над полем ввода.

### Как работает
- Микрофон слушается постоянно; речь режется **ПО ПАУЗАМ** (0.45 с тишины = конец фразы), не по секундам
- Каждые ~0.4 с текущий кусок прогоняется через GigaAM — слова появляются в облачке пословно
- После паузы фраза прогоняется начисто — точный текст с пунктуацией
- Лимит одной диктовки — **2 минуты** (было 5, снижено 03.11.2026)

### Облачко (`stream_overlay.py`)
- Позиция закрепляется один раз при старте диктовки; порядок поиска: каретка UI Automation (`_uia_caret_pos`) → каретка Win32 (`_caret_pos`) → рамка поля с фокусом (`_focus_rect`) → курсор мыши (`_cursor_pos`)

  | Где | Что срабатывает |
  |---|---|
  | Chrome/Edge, Telegram, VS Code, Electron, WPF (cTrader) | UI Automation: `TextPattern.GetSelection()` → каретка |
  | Блокнот, старые Win32/WinForms-поля | `GetGUIThreadInfo().rcCaret` |
  | Поле с фокусом без каретки | рамка поля, облачко по центру верхней кромки |
  | Ничего не найдено | курсор мыши (как раньше) |

- UI Automation подключается через `comtypes` (`UIAutomationCore.dll`), импорт обёрнут в try/except: без библиотеки остаются остальные три ступени. `GetCaretRange()` есть только в `IUIAutomationTextPattern2`, но Chromium его не отдаёт (`E_NOINTERFACE`) — поэтому позиция берётся из `GetSelection()` (при пустом выделении это вырожденный диапазон шириной 1 px в позиции каретки, правый край последнего прямоугольника).
- Свой процесс (`CurrentProcessId == os.getpid()`) в UIA-ветке и в `_focus_rect()` пропускается — облачко не цепляется к интерфейсу Talker Box.
- UIA отдаёт физические пиксели, `move()` ждёт логические — координаты делятся на `devicePixelRatio` (`_dpr()`).
- Первый запрос UIA к только что активированному окну может вернуть пустой прямоугольник `(0,0,1,0)` (холодное дерево доступности) — тогда облачко временно встаёт по Win32-каретке, а `_follow()` до 1,5 с (не больше 6 попыток) перепроверяет позицию через UIA и переезжает, когда та появится.
- Облачко висит **под** кареткой: `y = позиция каретки + CARET_GAP (20 px)`; если привязка к полю ввода — под полем (`низ поля + 20`). Если снизу не влезает в экран — уходит наверх над кареткой (запасной вариант)
- Текст растёт по ширине до 570 px (минимум 380), дальше — вниз
- Нижняя строка: `[Отправить]` (слева) | волна (центр) | таймер и крестик (справа) — всё цвета `#2e8b75`
- Волна — точная копия анимации капсулы (20 столбиков, синус), играет **только пока идёт речь**
- Кнопка `[Отправить]` — отдельное окно поверх (облачко прозрачно для мыши): курсор-«рука», ярче при наведении, звук `ping.wav`, клик = второй жм хоткея
- Шрифт и размер текста, кнопки и таймера — единый, берутся из настроек облачка
- Настройки облачка: фон/текст (палитра с тёмно-серыми подписями), шрифт (14/16/18), шрифт системы, прозрачность, микрофон
- Облачко ВКЛ → обычная капсула внизу скрыта; ВЫКЛ → капсула работает как раньше

### Отмена диктовки (правая кнопка мыши / крестик)
- Полная остановка сессии: следующий хоткей **сразу** начинает новую диктовку
- Красное «Сброшено — жмите хоткей заново» — исчезает само через 2 секунды
- Запоздалый текст отменённой диктовки не вставляется (3 уровня защиты: отключение доставки `on_phrase`, поколение сессии `_stream_epoch`, замок облачка `_flash_until`)

### Вставка текста — БЕЗ буфера обмена
- Текст **печатается символами** через SendInput (`KEYEVENTF_UNICODE`) — буфер обмена не затирается, скопированные картинки/скриншоты остаются целы
- Перевод строки = Enter, табуляция = Tab; авто-отправка = Enter в конце
- Пачка SendInput: если очередь ввода переполнилась (вернула меньше, чем послали), остаток добивается по одному — длинный текст больше не вставляется частично

### Отправка: текст ждёт в облачке (03.11.2026)

- **Остановка диктовки больше НЕ вставляет текст в поле.** Текст остаётся в облачке, его можно читать, править словарём и держать сколько угодно.
- **Следующее нажатие хоткея = отправка** (`send_pending()`): печатает ровно то, что сейчас в облачке (с правками), затем закрывает сессию.
- Клик по `[Отправить]` делает то же самое. Пока идёт речь — останавливает запись, после остановки — отправляет.
- Если облачко **выключено** в настройках — старое поведение: текст вставляется сразу после остановки (`TEXT_PASTE_DIRECT`).
- Финальный текст ASR приходит через ~3 с и заменяет живой в облачке, **но не затирает правки** (флаг `_cloud_edited`).
- Если распознавание вернуло пусто — берётся живой текст облачка (`TRANSCRIBE_FALLBACK`), надиктованное не пропадает.
- Запоздалые куски стрима после остановки игнорируются (`_on_stream_phrase`/`_on_session_text` проверяют `is_recording`) — правки больше не перебиваются.
- Закрытие облачка крестиком/меню = отмена: текст не ждёт отправки.

### Доставка текста в окно (03.11.2026, после «текст не отправляется»)

- Симптом был такой: в логе `SEND_PENDING` → `DO_PASTE` → `ok`, а в поле ничего. Причина — облачко и кнопка `[Отправить]` это отдельные окна: после клика по ним фокус остаётся у Talker Box, и символы SendInput уходят «в никуда».
- `_focus_target()` переписан: `AttachThreadInput` (обход запрета на смену активного окна) → `BringWindowToTop` → `SetForegroundWindow` → `SetActiveWindow` → возврат фокуса тому же элементу внутри окна через `GetGUIThreadInfo().hwndFocus`. Возвращает `True/False`, пишет в лог `FOCUS_TARGET` / `FOCUS_FAIL`.
- Перед печатью — пауза 120 мс, чтобы окно успело стать активным.
- Если окно назначения потеряно (закрыли чат) — текст **остаётся в облачке**, в таймере показывается «нет окна», в лог `PASTE_NO_TARGET`. Повторное нажатие хоткея отправит его ещё раз (цель берётся из текущего активного окна).
- `_has_pending_text()` больше не требует флага `_pending_send`: достаточно видимого облачка с текстом — хоткей и `[Отправить]` отправят его в любом случае.
- В логе видно, куда именно ушёл текст: `FOCUS_TARGET | hwnd=... fg=... ok=True/False`.

### Отправка после остановки: всегда сразу, правки учитываются (03.11.2026)
- **Быстрая отправка (03.11.2026):** по остановке печатается текст, уже видимый в облачке (SEND_FAST), без повторного распознавания всей записи — на двух минутах это экономило секунды. Полное распознавание запускается только если облачко пустое. Задержка от остановки до вставки — ~0,15 с (проверено на 2649 символах).
- Тайминги поджаты: вставка через 60 мс после остановки, пауза на активацию окна 80 мс, SendInput пачками по 128 событий с 4 мс (было 64/10 мс), Enter после текста через 80 мс.

- **Лимит одной диктовки — 2 минуты** (`QTimer.singleShot(120000)`, страховка в `transcribe_audio`: `elapsed > 125`). Было 5 минут — по решению пользователя хватает двух.
- **Весь текст живёт в облачке целиком**, без обрезки по символам (раньше стоял срез 600 символов — это и было «ограничение в 60 секунд»: ~10 символов в секунду речи). На двух минутах облачко ≈350–500 px высотой, всё выделяется и правится словарём.
- Правки, сделанные **по ходу диктовки** (выделил слово в облачке → «Добавить в словарь» → замены), применяются к полному тексту: замена идёт и по подписи облачка, и по всему `_stream_committed`, плюс пара (неправильное → правильное) копится в `_session_fixes` и применяется к финальному ASR.

- **Ждущего режима нет.** Остановка диктовки всегда сама вставляет текст в поле — без пауз и без «третьего нажатия».
- Правки, сделанные **по ходу диктовки** (выделил слово в облачке → «Добавить в словарь» → замены), применяются к финальному тексту:
  - `_session_fixes` — список пар (неправильное → правильное) на текущую диктовку, сбрасывается в `start_recording`;
  - в `on_text_ready` к тексту применяется `_apply_session_fixes()` (замена по целым словам), затем, если текст в облачке правили (`_cloud_edited`), берётся он.
- `_cloud_touched` остаётся только для лога (`STOP_SEND touched=… edited=…`).
- Логика `_autosend_*` и ключ `_keep_for_edit` из отправки убраны — они больше не влияют.
- **Куда печатать** (`_resolve_target`): берётся текущее активное **чужое** окно; если сверху наши окна (облачко/панель после клика) — последнее чужое окно, в котором пользователь реально работал (`_last_foreign`, обновляется опросом каждые 30 мс в `_check_rmb_reset`). Обход Z-порядка (`EnumWindows`) убран — он подхватывал случайное окно (например, открытый Word) вместо чата.
- В лог пишутся `SEND_TARGET` и `DO_PASTE ... target=0x… «заголовок» fg=…` — сразу видно, в какое окно ушёл текст.

### Отмена по Escape (03.11.2026)

- **Escape = крестик в облачке.** Во время диктовки — полный сброс (`_stream_reset`: «Сброшено — жмите хоткей заново», текст не вставляется). Если текст уже готов и висит в облачке — облачко закрывается, текст выбрасывается.
- Перехват — в `hotkey_hook.py`: у `HotkeyListener` появился `on_escape` и флаг `esc_enabled`. Флаг включается только пока идёт сессия (`start_recording`, `on_text_ready`) и снимается после отправки/сброса, поэтому в обычной работе Escape остаётся обычной клавишей.
- Нажатие **глушится** (`return 1`), чтобы Escape не сработал ещё и в активной программе; keyup тоже глушится.
- Если горячая клавиша сама — Escape, обработка отмены пропускается (`vk != self._main_vk`).
- В диалоге «Добавить в словарь» флаг снимается на время `dlg.exec()` — там Escape закрывает диалог, а не сессию.
- «Закрыть» в контекстном меню облачка → сигнал `close_requested` → тот же `cancel_session()`.

### Словарь неправильных слов (v2.3, в разработке)

Исправление слов, которые модель распознаёт неправильно (англицизмы, жаргон, имена).

### Как работает
- Слова лежат в **текстовых файлах** `vocabularies/*.txt` (любой Блокнот, формат: `Правильное слово - неправильный1, неправильный2`)
- **Все .txt файлы читаются автоматически** — тематики разными файлами (Медицина.txt, Программирование.txt…)
- **Варианты-маски**: `Time Web - ~тайм*` — звёздочка ловит семейство искажений (Таймвел, Таймвеб, Тайм-эп)
- Порядок правил: сначала точные варианты, потом маски (иначе маска съедает часть слова)
- Замена только по ЦЕЛЫМ словам (границы `(?<!\w)…(?!\w)`) — обычный текст не портится
- Кнопка «Открыть папку словаря» в Настройках; слова из облачка (ПКМ → «Добавить в словарь») дописываются строкой в конец `Словарь.txt`
- Строки `#` — комментарии (для памяток, например как произносить слово)
- **Буст слов в модели (hotwords) ВЫКЛ** — искажал распознавание; включается настройкой `vocabulary.hotwords` (экспериментально)

### Уроки
1. Английские слова при неверном произношении модель коверкает каждый раз по-новому — поэтому маски шире, чем списки вариантов
2. Правильное произношение терминов — главный фактор качества (дальность микрофона критична!)
3. Однобуквенные варианты (напр. «C» → «Seed») в словарь НЕ класть — портят обычный текст

### Статус (пауза)
- Ядро работает: замены, маски, добавление из облачка, текстовые файлы
- **Ждём хороший микрофон** — дальше финальное тестирование на чистом звуке
- В планах: UI-редактор словаря (дизайн-этап), озвучка правильного произношения, авто-обучение на исправлениях

## Загрузка модели (v2.0)

### Встроенная модель

- Определена в `settings_manager.py` как `BUILTIN_MODEL`
- Путь: `models/GigaAM/` относительно exe (в dev — полный путь)
- Тип: `sherpa-onnx` (NeMo transducer)

### Загрузка sherpa-onnx (`_load_sherpa_onnx`)

1. Ищет tokens.txt в корне и подпапках
2. Ищет encoder/decoder/joint по шаблонам
3. Пробует загрузить как NeMo transducer (с `model_type="nemo_transducer"`)
4. Если ошибка — пробует стандартный transducer (для Zipformer)
5. Если нет joint/joiner — пробует CTC (model.onnx + tokens)

### Обработка ошибок

- **При старте:** если модель не загрузилась → программа запускается без распознавания
- **При распознавании:** ловит исключения, пишет в лог

## Установка окружения одним скриптом (04.11.2026)

- `install_dev.bat` — тонкая обёртка: ищет Python (313 → Program Files → 312 → `where python`), вызывает `setup_dev.py` и делает `pause`. Ключи пробрасываются: `--check` (только проверить), `--run` (после установки запустить), `--no-model` (не качать модель).
- `setup_dev.py` (stdlib only, без сторонних пакетов) — 7 шагов: Python (3.12+, советует 3.13) → venv (сломанный переименовывается в `venv_broken` и создаётся заново) → пакеты из `requirements.txt` (ставит только недостающие, потом проверяет импортом и печатает версии) → модель GigaAM (проверка 4 файлов по размеру + докачка с HuggingFace через `urllib` с прогрессом, `.part` → `os.replace`) → файлы проекта и стартовый `vocabularies\Словарь.txt` → `py_compile` всех модулей `src` → загрузка модели `sherpa-onnx` (smoke-тест). В конце спрашивает «Запустить сейчас?», запускает через `pythonw`.
- Лог всех шагов — `setup_dev.log` в корне (в `.gitignore` через `*.log`). Коды выхода: 0 — всё готово, 1 — есть проблемы (список печатается).
- В консоли UTF-8: `chcp 65001` в батнике + `SetConsoleOutputCP(65001)` и `reconfigure` в скрипте. Все `subprocess.run` с `errors="replace"`, иначе кириллица pip ломает декодирование.
- Размеры модели для проверки (сверены HEAD-запросами к HF): `encoder.int8.onnx` 224570820, `decoder.onnx` 4600132, `joiner.onnx` 2712896, `tokens.txt` 13354.
- Проверено: `--check` на рабочей машине — все 7 шагов OK; `--check` на чистой копии без `venv` — внятная ошибка и код 1; `install_dev.bat --check` через cmd — работает; функция `download()` — качает `tokens.txt`. Полную докачку пакетов на этой машине не ждали (канал медленный, pip шёл ~1 МБ/3 мин), но механизм создания venv и запуска pip проверен.
